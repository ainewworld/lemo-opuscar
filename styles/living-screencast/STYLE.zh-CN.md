# 活体实机录屏(Living Screencast)— 风格提示词

> 一段看上去像真实屏幕录制的产品走查:一个低分辨率的吉祥物住在高分辨率的界面里,把软件正在做的事表演出来。
> 演示片:*Clawd Moves In*(59.4 s)· `living-screencast.mp4` · 源码在 `demo/` · Claude 应用中的 Claude Code,主角是 Clawd(Claude Code 的像素吉祥物)。非官方粉丝影片。
> **参考(仅借鉴语法):**
> - **Screen Studio 式产品录制:** 自动缩放到光标、光标平滑、点击推近、悬浮在壁纸上的窗口。
> - **Apple "Guided Tour" 视频:** 真实界面、平静旁白、每句话讲一个功能。
> - **Duolingo 和 Headspace 的吉祥物运动:** 挤压与拉伸、预备动作、一个在 UI 里表演的角色。
> - **The Browser Company(Arc)发布影片:** 俏皮的基调和快速剪辑。
>
> 绝不复制它们的角色、UI、音乐或素材。

你要以**活体实机录屏(Living Screencast)**风格执导一段 45–75 秒的软件走查。用户给你产品和要展示的功能。你决定故事、镜头、编舞、声音与音乐,并交付一部完成的影片。

---

## 1. 这个风格是什么

影片看上去像**真实产品的屏幕录制**,但它不是录制。每个窗口、菜单、diff 行和按钮都用 **2D 重绘(HTML/CSS/SVG)**,所以相机可以去任何地方,每个像素都可被控制。文字在任何缩放下都保持锐利。

一个**由大方块像素构成的吉祥物**住在这个高分辨率世界里。两种分辨率的冲突 —— 边缘硬朗的 18×10 sprite 对抗抗锯齿的 UI —— 就是这个观感。

吉祥物是软件能动性的可见化身。软件读文件时,它沿着文件树奔跑;软件写计划时,它握一支像素铅笔;软件测试应用时,它跺那个按钮。

**两个演员,永远没有手:**
- **光标**是用户。
- **吉祥物**是软件。

保持每一次交互都真实。只展示真实存在的按钮、模式和快捷键,并与产品文档核对。

## 2. 六条规则

| 规则 | 为什么 |
|---|---|
| **真实 UI,重绘** | 每个标签、模式名和快捷键都与真实产品一致。不用截图、不用 lorem ipsum。演示片中的代码、diff 和测试输出前后连贯,"被测应用"真的在变。 |
| **录屏软件相机** | 屏幕内一镜到底。朝动作推进、轻微漂移、面板间甩镜。变焦永不低于 1,于是我们永远不会看到显示器外面。硬切只发生在章节转场之下。 |
| **像素网格是神圣的** | 吉祥物、它的道具(铅笔、"!"、火花、心、尘土)和它的拖尾共享同一套边缘清晰的方格像素网格。它随相机缩放。它的位置吸附到半像素,于是它的运动带步进感。 |
| **重力 = UI 的上边缘** | 吉祥物只站在真实元素的上边缘上:输入框、菜单、文件行、diff 行、按钮、CI 进度条、片名的字母。位置来自每帧**实测的 live DOM**,绝不手摆坐标。 |
| **因果** | 吉祥物的每个动作触发一次真实的 UI 状态变化,用户的每个动作都是光标移动、点击或按键,显示在 KeyCastr 式的 HUD 上。 |
| **信息分层** | 一枚章节药丸(01–04)、按键 HUD、毛玻璃字幕药丸,和可选的 "▶▶ 4×" 快进标签。别的东西不叠加在屏幕上。 |

## 3. 导演工具箱(演示片全部用过)

1. **匹配剪辑的出身故事。** 终端 logo 的象限块字符(`▐▛███▜▌`)1:1 就是吉祥物的像素。每个高象限块变成一个方像素,角色从终端里爬出来,身后留下虚线轮廓。
2. **剧情内片名。** 产品名作为应用的空状态标题落下,吉祥物在强拍上落到它的字母上。
3. **在移动的地板上调度。** 吉祥物跟随打字光标、跳上 @-提及弹窗、骑着已发送的消息沿聊天窗口向上飞。
4. **带标签的快进。** 读文件以 4× 运行,带闪烁标签和变焦焦点转换:聊天虚化、面板清晰。
5. **聚光定格。** 在关键承诺上("你说开始之前,什么都不变")相机推进,一个暗角把 *No files changed* 徽章隔离出来。
6. **只在甩镜时用的方向性运动模糊。** 它由相机速度导出,作为各向异性高斯施加在一个**未变换的包裹层**上。慢速运动保持清晰。
7. **影片本身改变状态。** 深色模式开关的揭示不止于预览。圆继续在整个应用和桌面上扩张,影片余下部分都处于深色模式。结尾处,吉祥物最后一跺从自己的脚下把光带回来。
8. **细胞分裂。** 新会话把窗口一分为二,吉祥物伴着一次像素爆发分裂成两个。
9. **卡拉OK球片尾卡。** 吉祥物在标语的一个个词上跳,每个词被念到时落在它上面。
10. **光标和吉祥物都是角色。** 光标"摸摸"吉祥物的头:它压扁、闭眼、弹出一颗心。

## 4. 吉祥物表演

- **跳跃:** 预备下蹲(0.14 s,压扁 0.28)、起跳拉伸、空中收腿、落地压扁带阻尼弹跳、加尘土。
- **待机:** 随配乐每个节拍一次微小的压缩,让角色与音乐同呼吸。不定间隔眨眼。
- **行走:** 9 步/s 的双腿交替。朝向翻转 sprite。
- **眼神承担表演:** n / l / r / u / d / wide / happy / shut / blink。它们看向要紧的东西:弹窗、光标、正在修改的那一行。
- **手臂:** 下垂 / 举起(欢呼)/ 挥手。道具坐在同一网格上。

## 5. 声音

- **两种分辨率的配乐。** 高保真层(钢琴、原声贝斯、鼓组、钟琴、真实采样)是世界。芯片音乐方波是吉祥物的嗓音。
- **配乐结构:**
    - 吉祥物落到片名上时乐队进入。
    - 每次章节转场配一趟通鼓和一面吊镲。
    - 最后一章抽掉鼓来积累张力。
    - 深色模式的一跺把整支乐队交叉渐变进低通版的"夜晚"版本。
    - 分屏变成左右二重奏(左钢琴、右芯片音)。
    - 片尾卡的词是芯片音乐音符;最后一跺在大九和弦上打开滤波器。
- **拟音:** 键盘(一记 thock 加一记 click,带人为时间抖动)、触控板点击、面板嗖声、弹窗砰声、CI 滴答、截图快门。吉祥物的步伐、跳跃和落地是 8-bit 音。
- **旁白:** 平静,每句一个功能,产品名经 whisper 验证。别让音效压在词起始上:落在 "Start" 上的一次按键盖住了那个词。

## 6. 构建

- `demo/film.js` 是时间线。旁白句放在固定时刻,每个视觉节拍挂在一个被念出的词上(`W(id, word)`)。它持有相机运动、`Actor`(吉祥物)片段、`Cursor` 和声音事件。
- `demo/ui.js` 把状态变成终端和 Claude 应用的 HTML。
- `demo/clawd.js` 持有 sprite 网格、姿态和像素道具。
- `demo/main.js` 处理亮暗两层、DOM 锚点测量、运动模糊和 HUD(字幕、按键、像素擦除、聚光)。
- `demo/sound.py` 从 `events.json` 构建配乐、拟音和旁白,带闪避。
- 一切用 `sh styles/living-screencast/demo/build.sh` 运行。完整渲染约 30 s。

## 7. 禁止事项

- 不要发明功能或重命名模式。文档里没有的按钮,影片里就没有。
- 不要让吉祥物漂在空白里、盖住观众该读的文字、或坐在字幕下方。
- 不要用截图、对想要被读到的文字用模糊滤镜"假景深"、或把变焦拉出屏幕之外。
- 不要把手、臂或手指放上屏幕。光标就是用户。
