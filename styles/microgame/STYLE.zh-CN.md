# 微游戏快闪（Microgame Frenzy）— 风格提示词

> 一部快节奏的派对游戏影片：一个指令词、几秒钟、一个动作。每个微游戏都用一种完全不同的美术风格绘制，而且影片不断加速。
> 演示片：*Five-Second Astronaut*（五秒宇航员，59.8 s）· `microgame.mp4` · 源码在 `demo/`
> 类型参考（仅参考其语法）：瓦里奥制造（WarioWare）系列。绝不使用其名称、角色、UI、微游戏或音乐。

你正在以**微游戏快闪（Microgame Frenzy）**风格导演一部 45–60 秒的影片。用户给你一个主题。其余一切（故事、游戏、风格、节奏、声音）由你决定，并交付一部完成的影片。遵循本指南。

---

## 1. 这个风格是什么

一场游戏节目串联起一连串**微游戏**。每个微游戏 = **一个喊出的指令词 + 2.5–4 秒 + 一个动作 + 一个结果**（成功或滑稽的失败）。游戏之间影片切回**主舞台**：一位主持人、一块显示生命值和关数的记分板。每隔几个游戏，整部影片**加速（SPEEDS UP）**。结尾有一个更长的 **BOSS 关**，混合此前所有规则，并决定故事的结局。

这个风格成立的关键：**每个微游戏使用一种不同的视觉媒介。** 蜡笔、水墨、ASCII 终端、Risograph 孔版印刷、像素画、蓝图、瑞士排版等等。每次风格切换的冲击既是笑点也是节拍。主舞台是唯一固定的外观，把整部影片凝聚在一起。

## 2. 故事：什么适合这个风格

| 天生优势 | 故事用法 |
|---|---|
| **每个游戏一种风格** | 任何主题都可以拆成 6–8 个微型任务，每个用最适合它的媒介呈现。打喷嚏是一团墨渍；扣紧卡扣是一次继电器吸合；拉拉链是标注尺寸线上的刻度；跳跃是像素平台游戏。 |
| **指令词** | 一个动词就是整场戏：PUMP!（打气！）/ DON'T SNEEZE!（别打喷嚏！）/ ZIP!（拉上！）。它同时充当剧本、字幕和重拍。 |
| **生命值即 UI** | 头盔图标计数器不用旁白就能承载情绪。3 → 2 → 1（闪烁）本身就构建紧张感。 |
| **加速（SPEED UP）** | 五样东西一起加速：BPM、游戏时长、舞台停留、指令词保持时间、动画帧率。观众能感受到加速度。 |
| **Boss 混合规则** | 最终游戏由此前每种风格的碎片拼成，因此高潮部分 literally 由影片自己的过去构成。 |

**故事形态（已在演示片中验证）：** 冷开场从第 1 帧起就在某个游戏*内部*。第 1 轮一次滑稽的失败。第二次失败耗掉最后一条备用生命。最后一条命上的一个静默节拍。**转折：之前失败所用的素材在 Boss 关成为解决方案。** 演示片中，损失一条命的水墨喷嚏在高潮绽放成一顶水墨降落伞。结尾的呼应：角色重做之前失败的动作并做对了（敬礼）。

改编任何主题：从主题列出 7 个动词。给每个动词配上它最自然适合的美术媒介。让其中两个失败。让 Boss 关复用失败的那些。例如：一场产品发布变成 UNBOX!（开箱！，蜡笔）、PLUG IN!（插电！，蓝图）、DON'T DROP IT!（别摔了！，水墨）等等；Boss 关是 "SHIP IT!"（发货！）。

## 3. 视觉语言

**主舞台（唯一恒定的外观）**：扁平卡通，**7 px 近黑色描边 `#1a1030`**，平涂填色，以及**一块硬边缘阴影**——用阴影色填充形状、裁剪到自身、再向左上偏移 9 px 重填一次。调色板：舞台紫 `#2a0f5c` / `#3d168f` 旋转旭日纹、品红 `#ff2e88`、金 `#ffc928` / `#e08a00`、青 `#1fd1d1`、成功绿 `#3bdc5a`、失败红 `#ff3b3b`。固定道具：一块跑马灯招牌（片头卡）、中央的 **16:9 金色电视**（屏幕 768×432，恰为画幅的 1/2.5）、生命值头盔图标配板、关数徽章、以及带大红按钮的颁奖台。

**角色**（全部原创）：
- *主持人* = 一个金色**秒表头**。表盘即脸，红色秒针是他的指示棒和鼻子，他**拍打自己的表冠按钮**来开始每个游戏。他的指针每拍走一格，兴奋时旋转，最后一条命时戛然停住。
- *主角* = 2.3 头身的学员：泡泡头盔、带橙色小球的弹簧天线（**心情表**，每个动作都会 boing 一下），以及数字 "05"。
- **转写规则：** 在每种微游戏风格中主角都从零重绘，但**三个剪影标志永远保留**：圆头盔、天线球、"05"。见 `demo/stills/modelsheet_v2_styles.jpg`——同一个角色的 8 种绘制。

**微游戏媒介（简化重绘，各约 100–200 行代码）：**
| 风格 | 制作方式 |
|---|---|
| 蜡笔 | 画布上 RGB = 蜡笔颜色，**A = 压力**。着色器只在程序化纸纹 > 1 − 1.22·pressure 处沉积蜡。靛蓝色抖动轮廓、越线的锯齿排线，以及**挖空**：前景形状擦除其后的蜡。8 fps，线在 12 帧上抖动（line boil）。 |
| 水墨 | 两个通道：**R = 湿墨**（模糊、边缘颜料汇聚）和 **G = 干墨**（被纸纹打断）。笔触是带鬃毛轨迹的压力曲线；墨点是噪声圆盘；飞溅是甩出的墨点。唯一的颜色是一点朱砂：天线球，外加 "05" 印章。 |
| ASCII 终端 | **手写 ASCII 字符画主角**（亮度梯度会把小人物变成糊）。结构字形 `/ \ | _ -` 承载剪影。天线球是一个反显 `@`。琥珀荧光粉着色器，带辉光、3 px 扫描线和桶形弯曲。 |
| Risograph | 画布 **R/G/B = 蓝/黄/粉版密度**。`lighter` = 叠印（黄+粉 = 橙，黄+蓝 = 绿）；`source-over` = 挖空。7 px 旋转半调网点、每镜头固定的套印错位、以及关键动作时一次印版**甩动**。主角周围一圈纸白晕。 |
| 像素 | 240×135 索引帧缓冲 ×8。精灵由图元构建并带**自动 1 px 墨色描边**；辉光和火焰用 Bayer 抖动。12 fps。 |
| 蓝图 | 程序化蓝纸加 4 种粗细的白线、中心线/虚线、标注尺寸线、手写体字母，以及一枚红章。 |
| 瑞士 | 12 栏网格、单一无衬线字体族（Inter）、黑白加信号红 `#e30613`。主角是一个黑圆、一个黑矩形和一个**红圆**（天线球）。笑点是一个元素跑出网格。 |

**Boss 画面构图：** 最多混合五种媒介，但只有**一条视觉焦点链**：降落伞引向返回舱，返回舱引向靶子（复习课）。删掉一切跑题的东西，比如装饰性像素海鸥。把信息面板（ASCII 高度表）缩小到角落。图层：蜡笔以 alpha 模式渲染（蜡覆盖 = alpha，必须不透明处加全压力纸白底）；水墨和 riso 渲染在白底上并以 `multiply` 叠加；CRT 面板平涂渲染并裁剪到其框内。

**水墨降落伞（高潮）：** 必须*读作降落伞*，而不是烟。它分三阶段生长：返回舱舱口喷出的一股墨（0.15 s）、一滴**圆形**下坠扩散（短，0.3 s）、然后**9 片伞幅展开**。伞幅填充为垂直渐变（顶部密、下摆浅），交替 ±7 % 明度、细纸白缝线、以及荷叶边下摆（每片向下鼓）。伞顶有一笔饱满的笔弧、下摆有飞白、拉向舱口的是干细绳。

## 4. 动效语言

- **速度阶梯**（演示）：120 → 140 → 160 BPM。第 1 轮游戏为 2 小节（4.0 s），第 2 轮 1.5 小节（2.57 s）。舞台停留 1 小节 → 2 拍。指令词保持 0.75 s，之后 0.64 s。角色步进 8 fps → 12 fps → 24 fps（Boss）。摄影机运动、转场和引信火花始终逐帧（on ones）。
- **指令词**：Titan One，白字 22 px 墨色描边，后面一品红色坠子和金色爆光，斜切 −6°。它用 3 帧**砸入**（1.9 → 0.92 → 1.0），保持，然后在第一个动作之前**缩成角落标签**，避免盖住结果。一次性横幅（"BOSS STAGE!"、"PULL!"）直接飞出而不变成标签。
- **引信计时器**：底部一根编织绳，**每拍一个绳结**；火花恰好在节拍上越过每个绳结，最后到达一枚小鞭炮火箭。即时回放期间引信冻结，Boss 特写中隐藏。
- **统一转场 = 电视框**：舞台 → 游戏是摄影机推进电视屏幕（0.25 s）；游戏 → 舞台是整个画面缩回电视（0.33 s），并把 ✓ / ✗ 戳记拍在屏幕上。没有淡入淡出，没有空帧。
- **失败是演出来的，不只是展示**：水墨喷嚏糊满面罩，两只白眼睛从墨里眨出来。瑞士风格敬礼臂旋转超过 90°，*长出超过其模块长度*去拍红球，红球在基线上弹两下并滚出网格。
- **即时回放**用于故事关键的失败：定格 3 帧，然后 0.5× 播放并 1.4× 推近、黑边、用该风格自己的字体写 "instant replay"，然后恢复。代价 2 拍；音乐放一声唱片刮擦并降为半速。

## 5. 镜头语言

| 节拍 | 镜头 |
|---|---|
| 冷开场 | 第 1 帧已在一个游戏里，指令词正在砸入。规则在 1 秒内自我解释。 |
| 第一关 | 从电视里拉出：尺度揭示。游戏原来是节目里的一块屏幕。 |
| 舞台 | 永远是同一个正面、对称的"家"画面。只有记分板在变。 |
| 加速（标志性镜头） | 舞台裂成**三个老虎机滚轮**，带运动拖影地转出之前的游戏画面，并在 SPEED \| UP \| ! 上逐拍停下。 |
| 按钮 | Edgar-Wright 式**插入镜头**：手套在拍上砸下大红按钮的极端特写。 |
| 最后一条命 | 同一舞台但灯光切成一束顶部聚光；主持人静止。 |
| BOSS 关 | 8 块拼片（7 个最后帧加一张 BOSS 卡）在八分音符上翻入，再翻一次变成 Boss 画面的碎片。 |
| Boss 静默 | 推进到舷窗特写；观众先于主角看到尘埃。 |
| 高潮 | 墨色伞篷绽放时在一个节拍内猛切回全景。 |
| 结尾 | 回到主舞台；主角第一次站上它并敬礼；然后摄影机推进电视出片尾卡。 |

## 6. 声音

- **音乐优先**：在任何动画之前先写节拍网格（`timeline.js`）。每个重音都列入提示表（见 TREATMENT.md），画面对准它。`tools/cuecheck.py` 对照 `music/score.json` 检查 57 个画面事件（演示最大偏差 4.7 ms）。
- **配乐**：原创放克/流行融合。鼓组带 16 分音符踩镲和鬼音、**合成 slap 贝斯**（加性拨弦 + 带通拇指噪声 + 1.8–6.5 kHz 爆音 + 八度跳跃与滑音）、叠加铜管重音（trumpet_stac + alto sax + trombone_stac）、以及电钢琴音色（颤音琴+钢琴）。鼓和贝斯贯穿全片。其上，每种风格一件**色彩乐器**：木琴（蜡笔）、古琴泛音与滑音（水墨）、方波哔声（ASCII）、颤音琴与萨克斯（riso）、脉冲琶音（像素）、弱音小号（蓝图）、响棒与干钢琴（瑞士）。每次加速配一段上行的铜管跑句，调性每轮升全音。
- **真实的静默**：第一次喷嚏前 1 拍、最后一条命的舞台（只有心跳）、以及 Boss 特写（心跳 + 与第一粒尘埃相同的那个古琴音）。最大的重音紧跟最长的静默之后。
- **拟音跟随媒介**：蜡笔打气是橡胶吱吱声加充气声；水墨是湿拍和多滴滴落；ASCII 是电传打字键和继电器；riso 是纸闷响和咔嚓；像素是比特粉碎噪声；蓝图是棘轮齿和盖章闷响；瑞士是空腔 bonk 和小橡胶 boing。主舞台声音：弹簧表冠咔哒、失命时的玻璃碎裂加弹跳叮当、翻卡、老虎机滚轮嗡鸣、稀疏的采样掌声。
- **人声**：主持人 = Kokoro `am_fenrir`（在测试过的声音里音域最宽），语速 1.05–1.15。主持人在重音 *之后* 0.1 s 喊每个指令，避免铜管盖住词。主角 = `af_bella` 升调 +2.5 半音，只有 "Oh no." 加上 "ah… ah…" 和喷嚏，这些作为音效处理、豁免于耳语检查。人声下方音乐压低约 11 dB、拟音约 6 dB。
- **Kokoro 的单词指令**："Pump!" 会被读成 "Pompey"、"Zip!" 成 "Zipper"，因为加了元音尾。生成 "Pump, now!" 并按耳语时间戳在第一个词尾切断（`tools/trim_cmd.py`）。

## 7. 字幕与标题

- **指令词即字幕**：不重复烧录，只列入 .srt。
- 其他台词用**金色圆角卡**，7 px 墨色描边加硬阴影，Lilita One 50 px，配一个小秒表图标（主持人）或头盔图标（主角），游戏中放在引信上方。以 12 fps 分 2 步弹入。保持 ≥ max(1.8 s, 语音 + 0.6 s)，大横幅期间不出现。
- 片头卡是主舞台跑马灯逐字点亮（FIVE-SECOND ASTRONAUT / A MICROGAME FRENZY）。片尾卡在电视内：标题、风格名和 "LemoLab × Claude Opus 5.5"，配主角和主持人。

## 8. 我们踩过的坑

- 亮度梯度 ASCII 主角是读不清的糊。用手写模板加结构字形，天线球用反显 `@`。
- 水墨伞篷最初被读成黑烟或乌云。保持墨点阶段短而圆、用渐变和缝线展开伞幅、加荷叶边下摆、边缘留浅。
- 瑞士"敬礼失败"被读成举手。手臂必须*过冲并击中*红球，且失败需要即时回放才能在 140 BPM 下被理解。
- alpha 模式的蜡笔层会透过蜡的缝隙露出背景。在必须实心处给全压力纸白底（或渲染成不透明再裁剪）。
- 保存全局上下文（`K.g`）的卡通绘制助手，在场景渲染到离屏缓冲（电视屏、老虎机滚轮、拼片）时会画错画布。前后务必调用 `setCtx`。
- `flat` 是 GLSL ES 3 的保留字。
- 上传 2D 画布没设 `UNPACK_FLIP_Y` 意味着 v = 0 是画布顶部；用 `p/R` 采样。
- 指令标签堆积（同一角落 LAND IT! + PULL!）。次要指令应飞出，不打标签。
- 100 % 的白色冲击闪光被读成空帧；封顶 60 %。
- whisper 常在密集混音中听错 0.2 s 的指令词，即便信噪比 +16 dB。逐条剪辑验证，并在 300–4 kHz 频带测混音信噪比。
- zsh 的 `$T` 列表不做分词。使用 bash 审查助手 `tools/review.sh`。

## 9. 制作配方（本仓库）

```
styles/microgame/demo/
  timeline.js   tempo grid + segments (single source of truth)     film.js   assembly: stage, TV transitions, slot reels, boss tiles, end card, subs, events
  toon.js chars.js stage.js hud.js   home style, host & hero, stage, fuse/command/stamps/lives/subtitles
  glpass.js     WebGL2 material shaders: riso, crayon, CRT, ink, blueprint paper
  g_crayon.js g_ink.js g_ascii.js g_riso.js g_pixel.js g_blue.js g_swiss.js g_boss.js   one module per medium (scene + hero translation)
  frames.js     model sheets & style frames      music/score.py   original score      mix.py   foley + voices + ducking
  tools/        trim_cmd.py cuecheck.py subs.py final_asr.py review.sh mux.sh dump_timeline.mjs
```
1. 先写 `timeline.js`（节拍网格），再写提示表，然后把网格和提示表交给一个音乐子代理。与其并行地画画。
2. 先构建主风格和角色，然后**每种媒介一个 `sceneX(g, lt)`**。用 `?scene=g_x.sceneX` 静帧逐个审查。
3. `sh demo/build.sh` 重建一切：TTS → 裁剪 → whisper → 配乐 → 事件 → 提示检查 → 混音 → srt → 渲染（1436 帧约 25 s）→ 封装（−14 LUFS，噪点 0），总共约 1.5 分钟。
4. 用 `bash demo/tools/review.sh out/revN 6 $(seq 0.5 1 59.5)` 审查至少两遍，外加每个关键动作的帧条。
