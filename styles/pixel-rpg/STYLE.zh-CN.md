# 16-bit 像素 RPG(16-bit Pixel RPG)— 风格提示词

> 一部看起来、听起来并*表现得*像 90 年代中期主机角色扮演游戏的短片:320×180 像素、有限调色板、逐字打出的文本框、菜单、存档点、带回声的芯片音乐。
> 演示:*The Last Save Point*(54.5 秒)· `pixel-rpg.mp4` · 源码在 `demo/`

你正在执导一部 **16-bit 像素 RPG** 风格的 30–60 秒短片。用户给你一个主题。其余一切(故事、镜头、节奏、声音)由你决定,并交付一部完成的影片。遵循本指南。

---

## 1. 这个风格是什么

一个以 **320×180 原生像素**绘制的世界,用最近邻放大 ×6 到 1080p。每种颜色都来自**有限的、索引化的调色板**。渐变是**有序抖动**,而非混合。角色是约 22×34 px 的**精灵图**,用少量帧动画。故事以游戏的方式讲述:通过**带头像的对话框**、**菜单**、**状态栏**、**战斗信息**和**存档文件**。

它*不是* HD-2D(没有景深、没有泛光、没有实时光照),*不是* CRT 怀旧(没有扫描线、没有颗粒),也*不是*恶搞。它认真地把游戏系统当作一种表达情感的语言。

绝不使用现有游戏的名称、角色、UI 边框、字体、标志、旋律或音效。学习其语法,而非资产。

## 2. 故事:什么适合这个风格

挑选**游戏自身系统能承载情感**的故事。这种媒介有以下原生能力。至少使用三种,并把最强的放在情感高潮处。

| 原生能力 | 故事用途 |
|---|---|
| **调色板 = 情感** | 因为图像是索引化的,你可以在一帧内换掉整个调色板。记忆、悲伤、希望可以真的就是色彩深度。在演示中:越久远的记忆颜色越少(16-bit → 8-bit → 4 色)。失去之后的现在是**褪色的**。一段记忆的崩塌是调色板**每个节拍降一级**。希望是完整调色板**以有序抖动波的形式涌回**。 |
| **受保护的颜色** | 让少数几个调色板索引免受所有调色板效果影响。一件永不褪色的红色物品(围巾)成为贯穿全片的线索,也是跨越时代的完美**匹配剪辑**。 |
| **游戏 UI 即旁白** | 存档文件 = 一份记忆清单(选择 *NEW FILE* = 拒绝覆盖它们)。队伍列表中一个变灰的名字 = 死亡,无需一言。"No inn will ever heal it"(再多的客栈也无法治愈它)= 用媒介自身的词汇表达悲伤。 |
| **文本框与提示音** | 对话框*就是*字幕。一个没有配音演员、只有文字提示音的角色,读起来就是一个如今只存在于文字中的人。 |
| **时代切换** | 同一角色以更旧的硬件重绘:半分辨率下的 4 种明暗、13 色的 8-bit 套色、完整 16-bit。免费的时空旅行。 |
| **类型转换** | 温柔的记忆用马赛克淡入淡出。**遇敌漩涡**撞入危险。高潮处白闪。 |

改编任何主题:找到其中隐藏的**游戏系统**。产品发布 = 获得新道具(号角声、道具框、属性对比)。告别 = 一个永不被覆盖的存档文件。职业生涯 = 升级画面。一座城市 = 带存档点的大地图。

**45–60 秒的弧线:** 孤独(安静、褪色、长卷轴)→ 温暖(一段记忆)→ 失去(系统崩溃)→ 决心(系统以全彩恢复)→ 一张也是游戏提示的结尾卡(*CONTINUE ▶*)。

## 3. 视觉语言

- **分辨率与缩放**:原生 320×180 索引帧缓冲(调色板索引的 `Uint8Array`)。通过**查找表**(索引 → RGB)呈现,并以最近邻放大 ×6。所有内容,包括文字,都画在帧缓冲里。镜头运动按**整数像素**;每个视差层各自取整自己的偏移。
- **主调色板**:ENDESGA-32(`#be4a2f #d77643 #ead4aa #e4a672 #b86f50 #733e39 #3e2731 #a22633 #e43b44 #f77622 #feae34 #fee761 #63c74d #3e8948 #265c42 #193c3e #124e89 #0099db #2ce8f5 #ffffff #c0cbdc #8b9bb4 #5a6988 #3a4466 #262b44 #181425 #ff0044 #68386c #b55088 #f6757a #e8b796 #c28569`),外加**受保护的副本**(围巾红 `#e43b44/#a22633/#f6757a`,水晶青 `#2ce8f5/#0099db/#ffffff/#124e89`),任何调色板效果都不触碰它们。
- **色彩深度表**(全部由主调色板计算):
  - *16-bit*:恒等。
  - *8-bit*:最接近的 15 色 `#000000 #fcfcfc #a4a4b8 #58587c #1c2c8c #3c7cfc #94e0fc #b8141c #fc7454 #fcb81c #8c4c1c #2c9c2c #fcd8a8 #0c4c18 #4c2410`。需要深绿和深棕,否则夜草会变蓝。
  - *4 色*:固定亮度阈值(<60、<115、<175)→ `#1f2a1c #4b5e3a #93a263 #d6dba6`。用四个代表索引(墨/岩灰/钢灰/白)绘制 4 色场景,使每个像素落在预定的色调上。以 **160×90** 渲染再翻倍。
  - *褪色*:`lum^0.8 × 7` → 7 个蓝灰 `#0e0d17 … #c3c9d6`。**不要**按名次映射:名次映射会把画面压成一片黑。
  - *崩塌步骤*:16 色和 8 色子集要**保留暖色**(橙、粉、紫红),否则第一步就会让画面变红。之后是 4 个灰蓝、2 个色调、褪色。
- **光照即索引步进**:`LIGHT[]` / `DARK[]` 表让每个索引沿其色阶移动一步。火把光、月光和火焰是 `LIGHT[LIGHT[c]]` / `LIGHT[c]` 的 Bayer 阈值圆环。8-bit 场景中的火光使用**暖色重映射**(绿 → 棕 → 锈色),而不是普通提亮——后者会让草地像放射性物质。
- **抖动**:渐变和光晕用 4×4 Bayer。光柱用平整的 50% 棋盘格加 25% 边缘,比渐变更干净。
- **视差**(横版卷轴):带拱窗的远墙 0.35×,带旗帜和火把的柱廊 0.7×,带伪透视接缝的地面 1×,黑色前景立柱 1.6×。
- **精灵图**:一个**骨架**(胶囊形四肢,左上光源的三色调明暗,每个部件以材质最深色调描内线,全局 1-px 墨色轮廓)加上**手工摆放的 ASCII 头部**。一套骨架给出所有姿势:行走 ×4、攻击、受击、抬头、推、坐、跪、背面推。8-bit 场景用同一骨架但**去掉高光调**。给主角一个**剪影标记**:一条长围巾,尾端以 **3 帧阶梯循环**飘动,外加一撮呆毛。
- **头像** 32×32,3/4 视角,基础脸 + 眼/眉和嘴的覆盖层(平静、怅惘、微笑、悲伤、坚毅)。所有面部表演由它们承担;34-px 精灵的脸只有一像素的眼睛。
- **道具**:存档水晶是一个在 3D 中旋转的平涂明暗八面体,量化为 4 种受保护青色(每 90° 共 8 帧),带抖动光晕。巨门是正面透视的有镶板石门,带日纹山花、楔形拱石、开门时裂开的符文环,上方为仰摇准备的玫瑰窗。

## 4. 运动语言

- 输出 24 fps。精灵图以 **8 fps**(行走)到 **12 fps**(火焰、KO 闪烁)步进。镜头和视差以整数像素**逐帧(ones)**运动。行走速度 30 px/s ≈ 每帧 1.25 px。
- 游戏原生表演:向前跃出以行动,举起法杖的施法姿势,击退后坐,跪下,然后是 **KO 闪烁**(12 fps 亮灭)并消失。呼吸 = 肩膀上抬 1 px 持续 0.6 秒。
- UI 运动:窗口 0.3 秒滑入(ease-out,整数 px)。手形光标以 4 fps 上下浮动 1 px,并**在角色犹豫时停止浮动**。文字以 38–40 字符/秒打出(8-bit 为 30),完成后 ▼ 以 3 Hz 闪烁。
- 转场:**缩略图展开 + 马赛克**(块 10 → 1,历时 0.75 秒);**马赛克交叉**(1 → 16 → 1,历时 0.8 秒,调色板在峰值处切换);**遇敌漩涡**(极坐标扭转按 `s^1.6` 增长、马赛克、Bayer 溶解到白,0.8 秒);8 帧内 3–2–1 px 的**屏幕震动**;**调色板阶梯淡入淡出**(4 级),绝不用 alpha。

## 5. 镜头语言

| 节拍 | 镜头 |
|---|---|
| 开场 | 沿柱廊的长横移卷轴,主角很小(画面高度的 1/6),四层视差,前方一件彩色物品 |
| 菜单 | 固定机位,UI 在左三分之一,主角和道具在右侧可见 |
| 温暖的记忆 | 大远景,静止或缓摇;人物在天空或火光前显得很小 |
| 战斗 | 经典侧视:敌人在左,队伍在右面朝左,UI 窗口在下方,信息窗口在上方 |
| 失去 | 固定画面。调色板崩塌时不剪辑、不运动 |
| 纪念碑 | 沿一扇三屏高的门做**整数像素仰摇**至玫瑰窗,停住,再摇回。全片唯一令人难忘的镜头运动 |
| 高潮 | 门槛处的背面视角,光洒在地板上,色彩从主角向外涌出 |

## 6. 声音

- **音乐**:原创芯片音乐(方波 12.5/25/50%、4-bit 三角波、LFSR 噪声、波表)。一个动机以**地区变奏**贯穿所有段落。音乐的保真度跟随色彩深度:
  - 4 色:单声道、4-bit 音量步进、11 kHz 采样保持;
  - 8-bit:类 NES,单声道;
  - 16-bit:立体声,带 SNES 风格回声(3 抽头 ~180/270/370 ms,反馈 0.35–0.45,环路内低通 ~3 kHz);
  - 现在:同一段音乐变得沉闷(LP 2.2 kHz)。
  调色板崩塌期间,音乐每一步失去一层:和声,然后是回声和立体声,然后是低音,然后只剩单个方波音,最后在画面到达现在的灰色的那一刻**静默一拍**。首领前奏是小调化的动机;乐队全奏恰好在色彩涌回的那一小节进入。结尾卡解决开场停在属音上的乐句。
- **拟音**,全部合成并按场景时代做位压缩:光标/选择提示音、文字提示音(同伴的更高且为 5-bit)、带回声的石质脚步、火焰噼啪、结界微光(三角波琶音)、蓄力(上升方波 + 噪声)、爆发(扫频低通噪声 + 48 Hz 重击,压缩到 6-bit)、HP 递减声、KO 闪烁、每个调色板步骤一次的**位跌落**(一次比一次更低更粗)、存档滴答、门摩擦(棕噪声 + AM 嘎吱)、火把点燃、反向涌起。
- **一个有机声音**:主角在门前的呼吸,带通滤波的噪声,不做位压缩。它在最后一刻让他显得是人。
- **静默**:爆发之后(真正的零,回声尾也切掉)和到达"现在"之前的那一拍。
- **人声**:Kokoro `bm_george`,语速 0.9,第一人称,5 句短台词。人声下压音乐 ~−7.5 dB(60 ms 起音,350 ms 释放)。混至 −14 LUFS,**颗粒 0**。

## 7. 字幕与标题

- **对话框即字幕**,画在帧缓冲 y 134–176 处:
  - 三层圆角边框(墨/白/银);
  - 蓝→深蓝→夜的抖动填充;
  - 左侧 32×32 头像;
  - 原创变宽像素字体(大写高 7,x 高 5,下延 2),白色带 1-px 夜色阴影;
  - 随人声逐字打出;完成时显示 ▼。
- **皮肤随时代变化**:4 色场景为浅色框深色字,160×90;8-bit 为黑框白边加 8-bit 头像;16-bit/现在为蓝色(随现在褪色,色彩回归时变鲜艳)。
- 战斗信息放在顶部窄窗口。每个文本框停留 ≥ 1.8 秒且 ≥ 人声 + 0.6 秒。下一个框直接切掉上一个。`.srt` 从同一个 `window.SUBS` 数组导出。
- **标题**:两行,2× 字号,8 邻域墨色轮廓,按行白→银→钢灰渐变,Bayer 溶解进出。**结尾卡**:金色标题、闪烁的 `▶ CONTINUE`、风格名称、`LemoLab × Claude Opus 5.5`,以及红围巾飘过一次。

## 8. 我们踩过的坑

- **按名次的调色板映射把一切压成黑**:主调色板中深色很多,分位数映射会把半个画面放进最暗一级。用带伽马的亮度映射(`lum^0.8`)。
- **没有暖色的崩塌子集**会在第一步把日落变成纯红。16 色和 8 色集合中保留橙、粉和紫红。
- **8-bit 调色板没有深绿**:夜草变蓝。**火光旁的普通提亮**让草地变成霓虹绿。使用暖色重映射。
- **把全彩场景后量化到 4 色是一团泥**。原生地用 4 个已知索引以半分辨率绘制 4 色场景。
- 头发画成光滑圆顶读起来像头盔。背面头发用交替单像素读起来像锯齿噪声;用 2–3 个大尖角。奶油色束腰外衣读起来像裸露皮肤。法杖握在前手会在侧视中穿过脸部;握在后手置于身体之后。背在背上的剑会横过躯干正面;用髋侧剑鞘。
- 深色木板门读起来像监狱。用左上光照的斜切凹镶板、饰钉、拉环和山花。一个 bug 曾把关门的中缝画成了亮线。
- **负数取模**:`Math.floor(t*12) % 4` 在相位偏移使 `t` 为负时结果为负,索引到 `undefined`。用 `((n % m) + m) % m`。
- **同音词**:whisper 把 "inn" 听成 "in"。通过 `asr` 字段接受它;字幕负责消歧。
- 对话框占底部 25%。把地板线放在 y 128,站立角色保持在它上方。
- 受保护颜色上的匹配剪辑,要计算两个时代的屏幕坐标。演示中的围巾在两个时代都位于 (197, 104)。

## 9. 制作配方(本仓库)

```
styles/pixel-rpg/demo/
  px.js        indexed framebuffer, palettes & LUTs (full/nes/gb4/faded/c16/c8/c4/c2), dither, mosaic
  font.js      variable-width pixel font      ui.js        windows, dialog, menus, file list, status, save
  sprites.js   rig + ASCII heads, scarf tails portraits.js 32×32 portraits + expressions
  props.js     crystal, halo, pedestal, door  memsprites.js 4-color kid sprites
  scenes.js    corridor (parallax), door tilt, LIGHT/DARK index lighting, torches
  memscenes.js village (160×90), campfire (8-bit), battle (16-bit), thumbnails, title, end card
  main.js      director: shots, transitions, palette timing, EV (sound events), SUBS
  timeline.json single source of timing (music, picture, mix)   lines.json voice script
  music/score.py original chiptune from timeline.json            mix.py foley + voice + ducking
  sheet.js     model sheet (?sheet=1)          tools/subs.mjs srt export      build.sh one-shot rebuild
```

1. 先写 `timeline.json`:段落、BPM、强拍、重音点、静默、崩塌步骤。音乐、画面和混音都读它。
2. `?sheet=1` → 模型表;`?frame=corridor|door&lut=faded` → 在排镜头前做环境自检帧。
3. `core/tts/tts.py` → `asr_check.py`(全部 OK),然后对照时间轴编写 `music/score.py`(一个并行子代理效果不错)。
4. `node core/render/still.mjs demo --range 0.3:54.3:1.5` → `sheet.py` 总览;逐帧检查关键时刻。
5. `events.mjs` → `mix.py` → `tools/subs.mjs` → `video.mjs --workers 3`(1308 帧约 20 秒)→ `mux.sh … 24 0`。
6. `sh demo/build.sh` 从零复现一切。
